# S8C.0 — Provider authorization and security input

Research date: **2026-09-24**. The S8B `MarketplaceAccount` stores identity and an opaque protected credential **reference**, never tokens or app secrets ([ADR-0023](architecture/ADR-0023-s8b-commerce-foundation.md)). This document records official behavior and gaps for future connector design. It implements no authorization flow. Source catalog: [official evidence appendix](S8C0-OFFICIAL-PROVIDER-DISCOVERY.md#evidence-appendix).

Mercado Livre [documents](https://developers.mercadolivre.com.br/autenticacao-e-autorizacao) six-hour access tokens and single-use rotating refresh tokens; the latest refresh token supersedes the prior one and expires after six months. A refresh `invalid_grant` can mean expiry, reuse or revocation; seller reauthorization may be required. A future credential store needs atomic compare-and-swap/serialization per seller to avoid concurrent refresh races. This is a requirement derived from provider behavior, not a secret-manager choice. TikTok seller and Shopee lifetimes/rotation remain UNKNOWN.

## Scope and capability grant boundary

App-level availability, seller-granted scope and runtime success are separate observations. ML read/write permission is not blanket proof of Product Ads access [ML-ADS](https://developers.mercadolivre.com.br/pt_br/product-ads-para-catalogo-e-user-products-leitura). TikTok Finance explicitly needs `seller.finance.info` [TT-FINANCE](https://partner.tiktokshop.com/docv2/page/get-transactions-by-order), tracking names `seller.logistics` [TT-TRACK](https://partner.tiktokshop.com/docv2/page/get-tracking), and the product-performance API names `data.shop_analytics.public.read` [TT-ANALYTICS](https://partner.tiktokshop.com/docv2/page/get-shop-product-performance-list-202405). BR-local entitlement remains unresolved for tracking and product-performance. A creator token is not a Shop seller token. Record an account capability as GRANTED only after the relevant seller grant/eligibility is verified; a permission error is not evidence that the provider structurally lacks an API.

## Webhook and request integrity

- Mercado Livre [notifications](https://developers.mercadolivre.com.br/produto-receba-notificacoes) carry app/user/topic/resource and retry metadata. The official material accessed here does **not** establish a signature verification recipe or ordering guarantee. A future receiver must validate its own subscription context, account mapping, body bounds and replay key, then read the referenced resource with the seller's token. Avoid accepting event body values as canonical facts.
- TikTok Shop [Brazil invoice-status webhook](https://partner.tiktokshop.com/docv2/page/36-invoice-status-change) exposes `tts_notification_id`, `shop_id` and timestamp. The accessed page does not specify signature verification, retry ordering or general order event coverage. A future receiver must first obtain the official verification guide; until then, there is no safe implementation contract.
- Shopee notification topics, signature, challenge, retries and delivery guarantees are UNKNOWN because the current official documents were restricted.
- Outbound TikTok API request `sign` and path version are documented [TT-VERSION](https://partner.tiktokshop.com/docv2/page/api-versioning). This does **not** prove the inbound webhook signature format.

## Data minimization and retention

Brazil TikTok order responses can include CPF and CPF holder name for invoice processing [TT-BR](https://partner.tiktokshop.com/docv2/page/br-market-updated-api-workflow-to-support-order-invoice-and-warehouse). Mercado Livre orders may include buyer and shipping data [ML-ORDERS](https://developers.mercadolivre.com.br/pt_br/gerenciamento-de-vendas). Import only fields necessary for canonical Sale, order reconciliation, shipping display and legally required invoice flow, with explicit authorization/access controls for personal data. Do not persist full provider responses merely because they are available. Never log tokens, authorization codes, signatures, buyer documents, addresses or unredacted webhook bodies. Correlation IDs, resource IDs and sanitized failure codes may be retained for diagnosis.

S8B `MarketplaceListingObservation` already holds normalized facts under its 180-day policy. Future order/Sale retention follows Sales and applicable legal obligations, not the listing-observation period. Provider contractual storage/use/redistribution and BR-specific PII retention restrictions are **UNKNOWN** for the unverified flows and must be reviewed against official current terms before launch. TikTok [Partner Center terms](https://partner.tiktokshop.com/docv2/page/6506bbf2de672602b7bc0697) include Brazil-specific provisions; this discovery does not interpret them as a storage license. No raw-payload table or plaintext credential field is proposed.

## Future credential seam (proposal only)

A provider-neutral account authorization coordinator should resolve an opaque `CredentialReference` to protected provider material, scope-check per seller, serialize refresh, rotate atomically and surface `AUTH_RENEWAL_REQUIRED` or `USER_ACTION_REQUIRED` without changing structural capability state. A provider adapter owns its particular signing/token translation. Selection of vault, encryption library and webhook verification implementation waits for the current official Shopee/TikTok seller guides and implementation gate.

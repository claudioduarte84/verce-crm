# S8C.0 — Sync, pagination, limits and recovery

Research date: **2026-09-24**. This is a design input, not a scheduler or webhook implementation. `WEBHOOK_FIRST`, `POLLING_REQUIRED`, `HYBRID`, `MANUAL_ONLY` and `UNKNOWN` describe a future likely mechanism only where official evidence exists. All intervals and numeric quotas below are UNKNOWN unless explicitly sourced. Source catalog: [official evidence appendix](S8C0-OFFICIAL-PROVIDER-DISCOVERY.md#evidence-appendix).

## Notifications, identity and watermarks

Mercado Livre [notification documentation](https://developers.mercadolivre.com.br/produto-receba-notificacoes) names orders/items/shipments topics, resource references, retries, and missed feeds retained for **two days**. A handler should deduplicate by notification identifier/resource and seller, acknowledge only after durable receipt in a future design, and fetch canonical resource state. Delivery order and webhook signature are UNKNOWN; overlap polling is mandatory for gap recovery. Do not advance an order coverage watermark on receipt alone.

TikTok Shop's [BR invoice-status event](https://partner.tiktokshop.com/docv2/page/36-invoice-status-change) has a durable-looking `tts_notification_id` plus order/package references, but no guarantee was verified about globally unique scope, order or replay window. Treat it as an event deduplication candidate scoped by shop and topic, then confirm resource state. General order-event support, signing and retries remain UNKNOWN. Shopee events remain UNKNOWN.

For any future sync, persist a per-`MarketplaceAccount` + resource + provider version checkpoint containing: requested interval, provider cursor or timestamp filter, last successful page, completed-through time, and gaps/failures. A checkpoint is usable for `COMPLETE` coverage only when every relevant page has succeeded and cancellation/refund paths are reconciled for the requested period. For Mercado Livre, `order.date_last_updated` is a documented filter, but search's 12-month ceiling and canceled filtering impose a hard coverage caveat. For TikTok and Shopee, current history/update cursor semantics require official verification. Overlap length must be chosen from observed/provider-documented propagation, not guessed here.

## Rate limits and versioning

| Provider | Official evidence | What is still UNKNOWN | Future response |
|---|---|---|---|
| Mercado Livre | [429 guidance](https://developers.mercadolivre.com.br/pt_br/usuarios-e-aplicativos/rate-limit-erro-429); [notification retries](https://developers.mercadolivre.com.br/produto-receba-notificacoes). Resource-specific deprecations occur, e.g. User Products and Ads v2. | Universal global/per-app/per-seller numeric quota, quota headers, burst/daily allowances and all endpoint thresholds. | Per-provider/account/endpoint concurrency budget; 429 backoff with jitter and any documented `Retry-After`; observe current API docs/changelog before upgrades. |
| Shopee | Official current [documents portal](https://open.shopee.com/documents) restricted. | Every BR quota, header, 429 code, version/sunset rule and pagination standard. | No numeric budget or adapter until official BR docs. |
| TikTok Shop | [API versioning](https://partner.tiktokshop.com/docv2/page/api-versioning) puts v202309+ version in path; old versions have a minimum two-month availability and retirement notice. [Common errors](https://partner.tiktokshop.com/docv2/page/678e3a45786253031531b942) includes body code/message/request ID and rate/timeout classes. | Generic BR app/shop/endpoint numeric quotas, headers, burst/day budgets, exact BR order pagination and webhook delivery limits. | Rate budget per seller/resource; honor `Retry-After` if returned; pin each endpoint's documented version, monitor changelog and test upgrades. |

Do not transfer a number from an unrelated billing API, region or seller tier into a global quota. A successfully authenticated app can still receive a scope denial, moderation restriction or 429; none changes structural capability support.

## Retry and idempotency classification (conceptual)

| Class | Future rule | Evidence / qualification |
|---|---|---|
| `NON_RETRYABLE` | Reject/repair validation and malformed requests, unsupported category/attribute, impossible local mapping. | ML item validation [ML-PUBLISH](https://developers.mercadolivre.com.br/pt_br/publicacao-de-produtos); TikTok structured errors [TT-ERROR](https://partner.tiktokshop.com/docv2/page/678e3a45786253031531b942). |
| `RETRYABLE` | Retry idempotent GET after transient 5xx/timeout with bounded exponential backoff and jitter. | ML rate/error guidance [ML-RATE](https://developers.mercadolivre.com.br/pt_br/usuarios-e-aplicativos/rate-limit-erro-429); TikTok common errors [TT-ERROR](https://partner.tiktokshop.com/docv2/page/678e3a45786253031531b942). An ambiguous write is **not** safely replayable without reconciliation. |
| `RATE_LIMITED` | On 429/provider rate code, respect `Retry-After` when supplied, reduce concurrency and preserve checkpoint. | [ML-RATE](https://developers.mercadolivre.com.br/pt_br/usuarios-e-aplicativos/rate-limit-erro-429), [TT-ERROR](https://partner.tiktokshop.com/docv2/page/678e3a45786253031531b942); Shopee details UNKNOWN. |
| `AUTH_RENEWAL_REQUIRED` | Renew seller token once through provider-specific protected flow, then retry safe reads. | ML token renewal [ML-AUTH](https://developers.mercadolivre.com.br/autenticacao-e-autorizacao); TikTok/Shopee seller rotation specifics UNKNOWN. |
| `USER_ACTION_REQUIRED` | Stop on revoked grant, missing scope, app approval or seller eligibility; direct seller/admin to consent/approval. | ML revocation and invalid_grant [ML-AUTH](https://developers.mercadolivre.com.br/autenticacao-e-autorizacao); TikTok scope separation [TT-FINANCE](https://partner.tiktokshop.com/docv2/page/get-transactions-by-order). |
| `UNKNOWN` | Preserve raw provider code only in sanitized diagnostics; pause unsafe operation pending mapping. | Avoid treating undocumented write errors as retryable. |

No provider-wide POST idempotency key or safe publication replay guarantee was established. Future writes require a VERCE command identity, persisted desired state, operation result, provider ID lookup and read-after-write reconciliation before retrying an ambiguous outcome. Provider request IDs, when present (TikTok `request_id` [TT-ERROR](https://partner.tiktokshop.com/docv2/page/678e3a45786253031531b942)), should be logged without secrets/PII. No queue, cache, service or resilience library is selected here.
